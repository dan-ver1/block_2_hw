# Аналітика записів на курси

Streamlit-застосунок для аналізу таблиці `enrollments` навчальної бази PostgreSQL.

## Вигляд застосунку

![Дашборд: показники, розподіл статусів, топ-5 курсів і поле запитання до агента](docs/dashboard-overview.png)

Скріншот зроблено з локально запущеного застосунку. Для відтворення потрібні власні доступи
до навчальної бази та ключ Gemini; їх немає в репозиторії.

- **KPI:** кількість записів (записи на курси, а не унікальні користувачі), сертифіковані записи,
  частка сертифікованих записів.
- **Діаграма «Розподіл записів за статусом»:** горизонтальні стовпчики з підписами «кількість · частка»
  та українськими назвами: Переглянуто (`viewed`), Зареєстровано (`registered`), Досліджено (`explored`),
  Сертифіковано (`certified`). Статуси впорядковано за кількістю записів; послідовність етапів
  у даних не описана, тому діаграма не подається як воронка.
- **Таблиця «Курси з найбільшою кількістю записів»** під діаграмою: до 5 курсів — назва, спеціалізація,
  записи, сертифіковані записи та їхня частка від записів курсу. Курс — це `course_id` (курс у межах
  спеціалізації): однакова назва в різних спеціалізаціях рахується як різні курси. Порядок — за
  кількістю записів; частка не є рейтингом успішності, бо на меншій вибірці вона менш надійна.
- **Агент:** поле для запитання; агент на Gemini пояснює показники українською.
  Використані інструменти й модель показано в розкривному блоці «Технічні деталі».
- Методика розрахунку — у розкривному блоці «Як рахуються показники»;
  як працює агент — у розділі «Як влаштовано» нижче.

## Робоче визначення

Сертифікований запис — рядок `enrollments` з `funnel_state = 'certified'`.
Бізнес-визначення завершеного навчання **не підтверджене**.

`progress_pct` і `completed_at` не використовуються як критерій: дослідження даних показало
значення `progress_pct` понад 100 та заповнений `completed_at` у записах без сертифікації.
Тривалість навчання за датами не розраховується.

## Як влаштовано

| Файл | Призначення |
|---|---|
| `app.py` | інтерфейс Streamlit |
| `db.py` | підключення до PostgreSQL і фіксовані запити лише на читання |
| `agent.py` | агент Gemini з дозволеним набором інструментів |
| `.streamlit/config.toml` | світла тема інтерфейсу; без трасувань помилок у браузері |

- Агент бачить лише результати фіксованих аналітичних запитів і не виконує SQL.
  Числа обчислює код (`db.py`); Gemini лише пояснює їх.
- Агент може викликати тільки чотири інструменти без параметрів: KPI, розподіл за `funnel_state`,
  лічильники якості даних і топ-5 курсів за кількістю записів. Довільного SQL модель виконати
  не може, текст запитання в SQL не потрапляє, персональні та платіжні дані агенту не передаються.
- Топ-5 курсів рахується з'єднанням `enrollments` і `dim_course` за `course_id`
  (первинний ключ `dim_course`, тож з'єднання не множить записи).
- Підключення працює в режимі `READ ONLY` з обмеженням часу виконання запиту.
- Запити до Gemini: таймаут 60 с і обмежені повтори засобами SDK (до 3 спроб) лише для тимчасових
  помилок сервера (408, 500, 502, 503, 504) та обриву з'єднання. Помилка ліміту (429) не повторюється.
- Повідомлення в інтерфейсі розрізняють тимчасову недоступність Gemini, ліміт запитів,
  помилку доступу та недоступну модель; ключі й технічні деталі не показуються.

## Як запустити локально (Windows, PowerShell)

Потрібні Python, доступ до навчальної бази PostgreSQL і власний ключ Gemini API.
База даних і облікові дані **не входять** до репозиторію. Усі команди нижче виконуйте
в терміналі з кореня проєкту — папки, де лежить `app.py`.

1. Після завантаження проєкту створіть локальне віртуальне середовище та встановіть залежності:

   ```powershell
   python -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   ```

2. Створіть власний файл налаштувань із шаблону:

   ```powershell
   Copy-Item .env.example .env
   ```

   Відкрийте `.env` у редакторі та впишіть **свої** значення після `=`:

   | Змінна | Значення |
   |---|---|
   | `PGHOST`, `PGPORT`, `PGDATABASE` | адреса, порт і назва вашої PostgreSQL-бази |
   | `PGUSER`, `PGPASSWORD` | облікові дані бази (бажано користувач лише з правом читання) |
   | `PGSSLMODE` | за потреби розкоментуйте рядок у шаблоні та вкажіть режим SSL, який вимагає сервер |
   | `GEMINI_API_KEY` | ваш ключ Gemini API |
   | `GEMINI_MODEL` | доступна вашому ключу модель; у шаблоні вказано `gemini-3.8-flash` |

   У шаблоні лише `PGPORT` і `GEMINI_MODEL` мають прикладові значення; усі
   облікові дані залишено порожніми. Файл `.env` з реальними значеннями не
   надсилайте іншим і не додавайте до Git.

3. Запустіть сторінку разом з агентом:

   ```powershell
   .\.venv\Scripts\python.exe -m streamlit run app.py
   ```

   Відкрийте локальну адресу, яку покаже Streamlit у терміналі. KPI, діаграма
   й таблиця завантажуються з бази. Щоб звернутися до агента, введіть запитання
   у полі «Ваше запитання» й натисніть «Запитати». Окремо запускати `agent.py`
   не потрібно. Наприклад, запитайте: «Які курси мають найбільше записів?».
   Якщо вичерпано квоту Gemini, сторінка з даними залишається доступною, але
   агент не зможе відповісти до відновлення квоти.

4. Щоб зупинити застосунок, натисніть `Ctrl+C` у терміналі Streamlit.

Запити розраховані на навчальну базу з таблицями `enrollments` і `dim_course`
та полями, які використовує `db.py`. Для іншої структури бази знадобиться
адаптувати ці фіксовані запити.

## Підключення до бази: `.env` і MCP

- **Застосунок** підключається до PostgreSQL напряму через `psycopg`, читаючи змінні з локального `.env`.
- **MCP** (`course-db`) використовувався лише AI-асистентом під час розробки для дослідження бази.
  Застосунок від MCP не залежить.

## Інтерфейс

- Світла тема: дашборд переважно для читання чисел і пояснень; один акцентний колір (`#1D4F91`)
  для основної дії та сертифікованих записів, нейтральний сіро-синій для інших статусів.
- Контраст за WCAG: текст ≥4.5:1 (основний текст 14.8:1), межа поля введення і стовпчики ≥3:1.
- Однакова вузька колонка контенту на широкому екрані; на вузькому KPI-картки стають одна під одною.

## Безпека

- `.env` у `.gitignore` і не публікується; у репозиторії лише `.env.example` без облікових даних і ключів.
- Паролі, ключі та рядки підключення не виводяться в інтерфейс.
